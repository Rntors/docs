---
title: "Applications for bookings"
---

Use booking applications when customers should be able to discover a resource but an administrator must approve the reservation.

## Prerequisites

1. Enable the **Support** page.
2. Make Support visible to applicants so they can read administrator replies.
3. Enable booking notifications for the administrators responsible for applications.

## Understand booking permissions

Each resource has two controls:

- **Visibility** defines who can see it.
- **Booking** defines who can book it immediately.

When **Booking** is more restricted than **Visibility**, customers outside the immediate-booking group can submit an application instead.

## Configure applications

1. Open the resource settings.
2. Set the required **Visibility** level.
3. Choose a narrower **Booking** level.
4. Save the resource.

## Customer experience

The customer opens the resource, selects the desired date and time, and submits an application with the requested details. RNTOR creates a support request so the customer and administrators can continue the conversation.

## Manage applications

Administrators open **Support → Tickets**, review the requested schedule, and reply to the applicant. After agreeing on the details, create the booking for the customer and select the correct [payment method](/admin/billing/payments/payment-methods).

## Best practices

- Explain approval criteria in the resource description.
- Assign applications to a responsible administrator.
- Confirm availability before promising the requested time.
- Keep payment and cancellation terms in the ticket conversation.
